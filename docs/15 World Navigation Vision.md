# Noah's Seed
## World Navigation Vision

Version: 1.0

---

# Purpose

Noah's Seed is not intended to feel like a collection of menus.

It is intended to feel like a living world.

Children should naturally explore, discover, learn and play by interacting with that world, rather than selecting options from lists of buttons.

The interface should disappear into the experience.

---

# Guiding Principle

> Children interact with the world, not with menus.

Menus exist only when they improve usability.

The world itself should always be the primary interface.

---

# Long-Term Vision

When Noah starts the game he should not immediately see:

Garden

Library

Bedroom

Beach

Playground

Instead, he should see Noah standing inside his world.

Example:

                     ☀️

           🌳

🏡                     📚

        😀 Noah

🌱                     🚂

            🏖️

The child chooses where to go by interacting with the world.

---

# Navigation Philosophy

Movement should feel natural.

Examples include:

• Walking

• Running

• Riding a bicycle

• Riding a train

• Driving a vehicle

• Flying

• Fast travel (when appropriate)

The engine should support all movement methods.

The presentation layer determines how movement is shown.

---

# Places, Not Screens

The game is made up of places.

Examples include:

• Home

• Bedroom

• Garden

• Beach

• Playground

• Library

• Observatory

• Train Station

• Farm

• Aquarium

Internally these may be screens or scenes.

To the child they are simply places within the same world.

---

# Objects Drive Gameplay

Gameplay should emerge from interacting with objects.

Examples:

Garden Bed
→ Plant Seed

Tree
→ Water
→ Harvest Fruit
→ Observe Birds

Bookshelf
→ Read Book

Piano
→ Play Notes

Ferris Wheel
→ Ride

Train
→ Travel

NPC
→ Talk

The interaction belongs to the object, not to a menu.

---

# Entity Philosophy

Everything in Noah's Seed is an Entity.

Examples:

Player

NPC

Tree

Flower

Rock

Bug

Train

Book

Building

Pet

Vehicle

The engine treats these consistently.

Different behaviour comes from different components and systems rather than different architecture.

---

# Discovery Over Instruction

The child should discover opportunities naturally.

Instead of:

"Click Plant Seed"

the child notices:

🌱 Empty Garden Bed

and investigates.

Curiosity should be rewarded.

---

# Adaptive Presentation

Different children interact differently.

Some may prefer:

• Touch

• Mouse

• Keyboard

• Controller

• Voice

• Assistive technology

The engine should remain independent of the input method.

---

# Accessibility

The world should adapt to the child.

Navigation should never become a barrier.

Children requiring additional support should be offered:

• Simplified interaction

• Visual guidance

• Audio prompts

• Larger interaction zones

without changing the underlying engine.

---

# Future Expansion

This architecture should naturally support:

• Multiplayer

• Pets

• Vehicles

• Seasons

• Dynamic weather

• NPC schedules

• Adaptive educational content

• Mini games

without redesigning navigation.

---

# Success Criteria

A child should feel they are exploring a living world.

The interface should become almost invisible.

The game should encourage curiosity rather than menu navigation.

The world should invite exploration.

Children should feel they are visiting places, not opening screens.
