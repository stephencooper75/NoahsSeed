# Noah's Seed Development Workflow

Every development sprint follows this order:

1. Architectural Review
2. Project Status Dashboard
3. Risk Assessment
4. Recommendation
5. Files Affected
6. Complete Replacement Files (preferred)
7. Build Check
8. Browser Test
9. Console Verification
10. Next Sprint

Rules

- Prefer replacing entire files over partial edits.
- Every affected file must be listed before code is supplied.
- Browser startup sequence must be mentally verified before sending code.
- Never end a coding session with a knowingly broken build.
- Optimise for long-term scalability over short-term convenience.
